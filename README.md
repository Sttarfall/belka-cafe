# Кафе «Белка» — сайт с бэкендом и базой данных

Полноценное веб-приложение: сайт кафе + бронирование столиков + форма обратной связи +
админ-панель с редактированием меню. Все данные хранятся в настоящей базе данных (SQLite),
которая не пропадает при перезагрузке сервера.

## Что внутри

- `server.js` — сервер на Node.js/Express: отдаёт сайт и API
- `db.js` — работа с базой данных (файл `data/belka-db.json` создаётся автоматически,
  никаких дополнительных программ ставить не нужно — это обычный JSON-файл)
- `public/index.html` — сам сайт (дизайн, анимации, формы)
- `scripts/make-password-hash.js` — утилита для смены пароля админа
- `.env.example` — пример настроек, на основе которого нужно сделать свой `.env`

## Локальный запуск (для проверки перед загрузкой на хостинг)

1. Установите Node.js версии 18 или новее (https://nodejs.org)
2. В папке проекта выполните:
   ```
   npm install
   ```
3. Скопируйте `.env.example` в `.env`:
   ```
   cp .env.example .env
   ```
4. Придумайте пароль администратора и получите его хэш:
   ```
   npm run seed-password
   ```
   Скрипт спросит пароль и выведет строку вида `$2a$10$...` — вставьте её
   в `.env` как значение `ADMIN_PASSWORD_HASH`.
5. В `.env` замените `SESSION_SECRET` на любую длинную случайную строку.
6. Запустите сервер:
   ```
   npm start
   ```
7. Откройте в браузере `http://localhost:3000`

Пароль от админ-панели теперь тот, который вы задали на шаге 4 (ссылка «Панель
администратора» внизу сайта).

## Как это устроено (коротко, не для программиста)

- Меню, брони и сообщения хранятся в файле `data/belka-db.json`, который
  создаётся автоматически при первом запуске. Этот файл — и есть ваша база данных,
  его стоит периодически бэкапить (просто скопировать файл). Открыть и посмотреть
  его можно даже в обычном текстовом редакторе — это читаемый JSON.
- Пароль администратора нигде не хранится в открытом виде — только его
  необратимый хэш в `.env`. Если пароль забыт, нужно сгенерировать новый хэш
  через `npm run seed-password` и обновить `.env`.
- Сайт и сервер — это одно приложение: сервер отдаёт страницы и обрабатывает
  все формы и админку.

## Уведомления о новых бронях и сообщениях

Сайт может присылать уведомление на почту и в Telegram каждый раз, когда кто-то
бронирует столик или пишет через форму обратной связи — чтобы не заходить
каждый раз в админку и проверять вручную. Оба канала бесплатные и независимы:
если не настроить один, второй всё равно будет работать (а если не настроить
ни один — сайт продолжит работать как обычно, просто без уведомлений).

### Email (например, через Mail)

1. Зайдите в свой аккаунт Mail → **https://mail.ru**
2. Включите двухэтапную аутентификацию, если ещё не включена (Безопасность →
   Двухэтапная аутентификация)
3. Там же найдите **«Пароли приложений»** и создайте новый пароль для
   произвольного приложения — Mail покажет 16-значный код
4. В файле `.env` укажите:
   ```
   SMTP_HOST=smtp.mail.ru
   SMTP_PORT=465
   SMTP_USER=вашапочта@mail.ru
   SMTP_PASS=шестнадцатизначный-пароль-приложения
   NOTIFY_EMAIL_TO=вашапочта@mail.ru
   ```
   (можно указать в `NOTIFY_EMAIL_TO` другую почту, если письма должны приходить
   не туда же, откуда отправляются)
5. Перезапустите сервер

Подойдёт и другая почта (Yandex, Google, корпоративная) — просто узнайте у
её справки данные для SMTP (host и порт) и используйте пароль приложения,
если сервис его требует.

### Telegram

1. В Telegram найдите бота **@BotFather**, напишите ему `/newbot` и следуйте
   подсказкам (укажите имя бота) — в конце он даст вам **токен** вида
   `123456789:AAExampleTokenHere`
2. Найдите своего нового бота по имени, которое вы ему дали, и напишите ему
   любое сообщение (например «привет») — это нужно, чтобы бот вообще мог
   вам писать
3. Откройте в браузере ссылку (вместо `<ТОКЕН>` вставьте свой токен):
   ```
   https://api.telegram.org/bot<ТОКЕН>/getUpdates
   ```
   В открывшемся тексте найдите `"chat":{"id":123456789` — число после `id` —
   это ваш `TELEGRAM_CHAT_ID`
4. В файле `.env` укажите:
   ```
   TELEGRAM_BOT_TOKEN=123456789:AAExampleTokenHere
   TELEGRAM_CHAT_ID=123456789
   ```
5. Перезапустите сервер

После перезапуска в терминале появится строка, настроены ли уведомления:
```
✅ Email-уведомления настроены
✅ Telegram-уведомления настроены
```
Если видите вместо этого «не настроены» — проверьте, что в `.env` нет пропущенных
значений и нет лишних пробелов.

## Куда выложить сайт (варианты хостинга)

Так как база данных — это обычный файл на диске, важно выбрать хостинг, который
**не пересоздаёт файловую систему при каждом перезапуске/деплое** (иначе меню и
брони будут обнуляться). Подойдут:

### Вариант А — Render.com (просто, недорого)
1. Загрузите этот проект в свой репозиторий на GitHub.
2. На render.com создайте **Web Service**, подключите репозиторий.
3. Build Command: `npm install`, Start Command: `npm start`.
4. Добавьте Persistent Disk (постоянный диск) и примонтируйте его в папку `data/`
   — иначе база данных будет стираться при каждом деплое.
5. В разделе Environment добавьте переменные из `.env` (`SESSION_SECRET`,
   `ADMIN_PASSWORD_HASH`, `NODE_ENV=production`).

### Вариант Б — обычный VPS (свой сервер)
1. Установите Node.js на сервере.
2. Скопируйте проект, выполните `npm install --production`.
3. Создайте `.env` так же, как локально.
4. Запускайте через процесс-менеджер, чтобы сайт работал постоянно и
   перезапускался при сбоях, например через `pm2`:
   ```
   npm install -g pm2
   pm2 start server.js --name belka-cafe
   pm2 save
   ```
5. Настройте Nginx как обратный прокси на порт из `.env` (по умолчанию 3000)
   и подключите SSL-сертификат (например, через Let's Encrypt / certbot) —
   это нужно, чтобы админ-панель работала по HTTPS.

### Вариант В — Railway.app
Похоже на Render: подключаете GitHub-репозиторий, добавляете переменные
окружения и постоянный volume для папки `data/`.

## Важно перед реальным запуском

- Обязательно смените `ADMIN_PASSWORD_HASH` и `SESSION_SECRET` — те, что в
  примере, использовать нельзя.
- Сайт должен работать по HTTPS (у всех перечисленных хостингов это есть
  «из коробки» или настраивается бесплатным сертификатом) — иначе сессия
  администратора не будет сохраняться в браузере.
- Периодически делайте резервную копию файла `data/belka.db`.
- Замените карту, адрес, телефон и ссылки на соцсети в `public/index.html`
  на настоящие данные кафе — сейчас там демонстрационные заглушки.
- Замените декоративные плейсхолдеры в разделе «Фото» на настоящие фотографии
  кафе (потребуется доработать вёрстку под `<img>`, сейчас это цветные блоки).

## Ограничение этого проекта

Это одностраничный сайт + простой API — для одного кафе с умеренным
количеством посетителей этого достаточно. Если в будущем понадобится
больше функций (личный кабинет гостя, онлайн-оплата, интеграция с CRM,
рассылки) — потребуется расширение бэкенда.
